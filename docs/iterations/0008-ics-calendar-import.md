# Iteration 0008: ICS Calendar Import

状态：Implemented and verified

## 目标

在账号授权同步之前，为第一代提供一个跨日历产品可用的真实日程来源，并确保导入不会静默覆盖用户已有安排。

## 本轮完成

- 新增 Rust `calendar_import` 模块，通过 `icalendar 0.17.12` 解析 RFC 5545 文件。
- 支持 UTC、浮动本地时间、IANA `TZID` 和常见 Windows 时区别名。
- 支持 RRULE、RDATE、EXDATE、全天事件、跨日事件和取消事件。
- 重复实例以 UID 和原始实例时间生成 SHA-256 稳定 ID；SQLite 不保存原始 UID。
- 前端提供文件选择、解析状态、来源摘要、事件列表、重复标记、跳过项和警告。
- 导入预览会与现有计划时间块检测重叠并显示冲突对象。
- 用户确认后只更新同 ID 日历项并追加新项，保留所有其他手动、Agent 和锁定时间块。
- 导入项标记为 `source: calendar` 和 `locked: true`，可直接作为早晨规划器的固定约束。
- 浏览器开发模式保留入口，但不读取日历内容，明确提示原生桌面版要求。

## 隐私与可靠性边界

- 原始 ICS 文本仅在内存中解析，不写入 SQLite。
- 不读取或保存地点、描述、参与人和附件。
- 单文件限制 2 MB，最多 5000 个原始事件、500 个当天预览项、每个规则 512 个实例。
- 无结束时间的普通事件以 30 分钟预览并给出警告。
- 无法识别的时区、无效时间和异常重复规则会跳过并显示警告。
- 冲突只提示，不自动移动、删除或缩短任何计划。

## 验证证据

- `npm run build` 通过。
- `cargo test --lib`：19 项通过，2 项需要真实 Codex 登录环境的测试忽略。
- 日历单元测试覆盖 UTC 到 Asia/Shanghai 换算、RRULE 每日展开、跨日裁剪、全天事件、取消事件和 Windows 时区别名。
- 浏览器交互验证：导入对话框可打开；选择示例 ICS 后显示桌面版降级提示，确认按钮保持禁用。
- `git diff --check` 通过，仅存在仓库原有的 Git CRLF 提示。
