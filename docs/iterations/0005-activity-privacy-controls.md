# Iteration 0005: Activity Privacy Controls

状态：Implemented and verified

## 目标

完成前台活动采集的隐私闭环，让用户能明确控制采集范围、敏感应用和本地数据生命周期。

## 本轮完成

- SQLite 数据库升级到 v5，新增 `activity_exclusions` 表和 `activity_retention_days` 设置。
- 默认保留期限为 30 天，可选 7 天、30 天、90 天或 1 年。
- 排除应用按进程应用名精确匹配，忽略大小写，最多保存 100 项。
- 数据库写入前强制检查排除表，不能由前端绕过。
- 保存排除列表时立即删除这些应用已经存在的活动记录。
- 应用启动和后台每小时自动清理过期活动。
- 新增独立的清空活动历史命令，界面要求二次确认。
- 设置对话框同时管理活动追踪、脱敏窗口标题、应用排除和保留期限。

## 隐私规则

- 活动跟踪和窗口标题仍默认关闭。
- 排除应用名只保存在本机 SQLite，不写浏览器存储或日志。
- 缩短保留期限后立即执行删除，而不是等待下一次后台任务。
- 清空活动历史不删除日程和 Agent 事件，避免扩大破坏范围。

## 验证证据

- Rust 测试验证大小写无关排除、既有历史删除、过期清理和全部清空。
- 浏览器交互验证添加排除项、切换 7 天保留、二次清空确认和保存后关闭。
- 设置对话框使用原生 modal dialog，支持焦点约束和 Esc 关闭。
- `npm run build` 和 `cargo test --lib` 通过。

## 后续

- 增加活动分类修正和按日期范围删除。
- 明确 Agent 事件与截图导入文件各自独立的保留策略。
