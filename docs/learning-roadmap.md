# Agent Bar 学习路线

状态：Draft v0.1

## 目标

这个项目不仅要能运行，还要让项目负责人能够在简历和面试中独立解释需求、架构、关键实现、权衡、测试和问题排查。

不要求记住每一行代码，也不要求在开始前掌握所有框架。每个阶段需要达到三个标准：

1. 能说明这一层解决什么问题。
2. 能读懂并修改核心实现。
3. 能解释为什么选择当前方案，以及替代方案的取舍。

## 阶段一：Web 与桌面界面基础

需要掌握：

- TypeScript 类型、异步流程和模块组织。
- React 组件、状态、Effect 和事件处理。
- DOM/SVG 的时间轴布局、缩放、拖拽和无障碍语义。
- Canvas 2D 的坐标、绘制循环、Sprite 和点击命中。
- Tauri 的前端与 Rust 端边界、command 和 event。

阶段产物：使用模拟数据完成 SVG 时间轴和 Canvas 像素办公室原型，并能说明 React DOM、SVG 与 Canvas 为什么分工。

## 阶段二：本地数据与时间建模

需要掌握：

- SQLite 表结构、索引、迁移和事务。
- 时间区间、时区、重复日程和计划/实际数据分离。
- Windows 前台应用和窗口采集的基本原理。
- 隐私脱敏、排除列表和本地数据生命周期。

阶段产物：完成一天的计划与实际活动记录，并能解释数据模型和隐私设计。

## 阶段三：实时事件与 Agent 适配

需要掌握：

- HTTP、WebSocket、事件流和断线重连。
- Provider adapter、能力声明和统一 AgentEvent。
- Codex Hooks 的生命周期事件。
- Codex SDK/App Server 的 thread、turn、approval 和 interrupt。
- MCP 的 tool/resource 边界，以及 Skill 与 MCP 的区别。

阶段产物：Codex 活动驱动像素角色动画，并完成至少一次受控的批准或终止操作。

## 阶段四：日历与外部服务

需要掌握：

- OAuth 2.0、访问令牌和最小权限。
- Microsoft Graph 日历事件、增量同步和冲突处理。
- Notion/飞书 API 的分页、限流、Webhook 或事件订阅。
- 外部写入的幂等性、来源记录和失败重试。

阶段产物：从一个正式日历读取日程，由 Agent 生成当天计划，并在确认后写回。

## 阶段五：测试与项目表达

需要掌握：

- Vitest 单元测试、Playwright 端到端测试。
- 适配器契约测试和模拟事件回放。
- 日志、错误分类和可复现问题报告。
- README 演示、架构图、性能指标和隐私说明。

阶段产物：可安装的 Windows MVP、演示视频、完整 README 和可量化测试结果。

## 与 Codex 协作的学习规则

- 每个里程碑开始前先解释设计，再写代码。
- 核心模块完成后由项目负责人复述数据流和关键权衡。
- 对不理解的代码立即补学习笔记，不累计“看不懂但能跑”的代码。
- 每个 PR 记录一个架构决定、一个遇到的问题和一个验证方法。
- 项目负责人亲自完成部分关键改动和调试，确保能够现场讲解。

## 简历价值判断

项目最有价值的内容不是使用了多少框架，而是能够证明：

- 发现并定义了真实的人机协作问题。
- 设计了统一的人类活动与 Agent 事件模型。
- 实现了 Windows 桌面采集、实时事件和多 Agent 适配。
- 处理了隐私、授权、失败恢复和跨服务一致性。
- 用真实使用数据验证了时间规划和 Agent 可观察性的价值。
