# Iteration 0011: Real Time Statistics

状态：Implemented and verified; category correction and idle detection remain pending

## 目标

把“今日投入”和周视图从固定示例数字升级为由真实计划与前台活动记录计算的时间去向，让计划、实际和应用使用形成可核验闭环。

## 本轮完成

- 新增纯 TypeScript 时间统计模块，统一类别汇总、Top Apps、重叠计划去重、本地周边界和时长格式。
- 今日投入展示真实总时长、计划占用、专注/会议/事务/生活四类时长以及使用时间最长的三个应用。
- 周视图按周一至周日展示每天实际类别构成，并同时显示当天已记录/计划时长。
- 浏览器开发模式由时间轴示例记录动态计算，不再维护第二套固定统计数字。
- 新增原生 `load_activity_week_summary` 命令，从 SQLite 读取一周活动和计划。
- 前端把七个本地日界线传给 Rust，兼容 23/24/25 小时的本地日期；Rust 要求日期连续、时间范围连续且单日不超过 26 小时。
- 跨午夜活动在每个本地日范围内裁剪后聚合，不把整段错误计入任意一天。
- 计划总时长使用区间并集合并，冲突或重叠安排不会重复计时。
- 类别和应用时长在毫秒级累加后统一四舍五入到分钟，减少短记录逐条取整误差。
- 周统计每 30 秒及窗口重新可见时刷新；隐私排除或清空历史后立即同步更新。

## 数据不变量

1. 一周查询必须包含七个连续、无缝衔接的本地日期范围。
2. 活动只统计与目标日期真实相交的区间。
3. 重叠计划按占用时间并集计算，不重复增加计划总时长。
4. 未识别的历史类别归入事务，保证分类合计与实际总时长一致。
5. Top Apps 只使用应用名称和聚合分钟，不读取或暴露窗口标题。
6. 浏览器演示数据与桌面 SQLite 数据使用同一前端展示模型。

## 验证证据

- Node 测试 18 项通过，其中 6 项覆盖类别与应用汇总、边界裁剪、计划区间并集、本地周范围、浏览器周映射和时长格式。
- Rust 测试 22 项通过，2 项真实 Codex 登录测试忽略。
- 数据库测试覆盖活动从前一天跨入周一、周一跨入周二、同日多应用，以及两个重叠计划只计 90 分钟。
- `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- 1280x720 验证：7 天统计行和条形图均在容器内，页面无横向溢出。
- 390x844 验证：每日“实际/计划”数字和类别条不截断，页面无横向溢出。
- 浏览器计算结果：示例活动共 `6h 17m`，其中专注 `4h 41m`、会议 `1h 6m`、事务 `30m`，Top Apps 排序与原始时间块一致。
- 浏览器控制台无 warning 或 error。

## 当前限制

- 活动类别仍由应用名称启发式判断，用户还不能纠正历史类别或配置规则。
- 尚未检测键鼠空闲、锁屏和离席时间，打开的前台应用仍可能被视为持续使用。
- 当前周视图只显示本周，不支持切换历史周、趋势比较或导出。
- 浏览器演示仅有当天示例活动；Tauri 模式会读取 SQLite 中完整一周。
