# Iteration 0007: Tray Recovery

状态：Implemented and verified on Windows; shutdown behavior remains pending

## 目标

为常驻状态条建立独立于窗口点击区域的恢复入口，避免点击穿透、隐藏或紧凑模式把用户锁在界面之外。

## 本轮完成

- 使用 Tauri 2.11.5 `TrayIconBuilder` 创建系统托盘图标和原生菜单。
- 托盘菜单包括展开工作台、显示顶部状态条、恢复交互并展开、退出 Agent Bar。
- 关闭主窗口时阻止窗口销毁并隐藏到托盘。
- 只有托盘的明确退出命令调用 `AppHandle::exit(0)`。
- SQLite 数据库升级到 v6，保存 `expanded` 或 `compact` 窗口模式。
- 应用启动时恢复上次窗口模式。
- 托盘和顶部按钮复用同一个原生窗口状态机。
- 托盘切换后通过 `window-mode-changed` 事件同步 React 状态。

## 恢复不变量

“恢复交互并展开”会依次执行：

1. 显示主窗口。
2. 关闭点击穿透。
3. 恢复普通层级、装饰、阴影、缩放和最小尺寸。
4. 调整为居中的 1440×900 客户区。
5. 取消最小化并获取焦点。
6. 通知前端切换到展开布局。

## Windows 实机证据

第一组探针从 `1920×68 + Topmost + WS_EX_TRANSPARENT` 开始，恢复后得到：

- 客户区 `1440×900`。
- Topmost 为假。
- `WS_EX_TRANSPARENT` 为假。
- 窗口可见且进程响应正常。

第二组探针对主窗口发送 `WM_CLOSE`：

- 关闭后窗口不可见，但进程保持存活。
- 通过托盘共用恢复函数后窗口重新可见。
- 恢复过程没有启动活动跟踪或 Agent 模型调用。

托盘构建失败会使 Tauri setup 返回错误；实机进程持续运行说明托盘资源和菜单成功创建。

## 当前限制

- 尚未通过自动化直接点击 Windows 通知区域中的菜单项；当前验证覆盖菜单构建和菜单复用的恢复函数。
- 正式 UI 尚未开放点击穿透开关。
- 系统关机、注销、Explorer 重启后托盘图标恢复尚未验证。
- 暂无全局快捷键作为第二恢复通道。

- 验证 Explorer 重启、系统关机和休眠唤醒。
