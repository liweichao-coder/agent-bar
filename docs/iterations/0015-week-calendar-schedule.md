# Iteration 0015: Week Calendar Schedule

状态：Implemented and verified for bounded seven-day local-file sync, atomic source replacement, and responsive week schedule rendering

## 目标

把持续日历连接从“只更新今天”推进到真正可使用的周视图：一次同步取得当前周七天的固定安排，任何一天失败都不能留下半周新、半周旧的数据；界面则用统一的 24 小时坐标让用户快速观察每天的时间窗口。

本轮继续保持只读边界，不把 OAuth、远端写回或后台服务伪装成已完成能力。

## 本轮完成

- 新增 `ScheduleDay` 周日程传输模型和 `load_schedule_days` Tauri 命令，一次返回有序的多日日程。
- 持续连接同步接受 1 至 14 个日期，并验证当前日期在范围内、日期有效、无重复且连续递增。
- 每个日历连接只读取文件或 HTTPS 内容一次，再对同一份 ICS 按各本地日期展开，避免按天重复下载。
- 所有日期都解析成功后，SQLite 才在单个事务中按 `calendar:<connection-id>` 删除并写入该来源的各日日程。
- 任一天写入失败会回滚整批操作；其他日历连接、手工块、Agent 块和一次性导入块不受影响。
- 同步结果同时返回连接状态、当前日程和整周 `scheduleDays`，日视图与周视图共享同一批真实数据。
- 新增本周安排界面：周一至周日共用 00:00 至 24:00 坐标，时间块按类别着色，锁定日历块带标记，可点击查看日期、时段和来源。
- 纯函数为重叠事件分配最多四条轨道；非重叠事件复用轨道，过密安排保留明确的隐藏数量提示。
- 820px 全天画布在自己的区域内横向滚动，桌面端可与 Agent 办公室并排，390px 窄屏不会撑宽整页。
- 周视图使用原生按钮、有序列表、可聚焦滚动区、可读标签和 `aria-live` 详情区，键盘和辅助技术无需理解像素位置。

## 数据与事务不变量

1. 同步范围必须包含当前日期，且最多 14 个连续本地日期。
2. 单个连接每轮只取得一次原始 ICS；网络与文件大小限制继续沿用 0014。
3. 任何日期解析失败时不开始替换，旧日程完整保留。
4. 数据库替换按连接来源和日期双重限定，不能删除其他来源的数据。
5. 多日删除和插入属于同一个 SQLite 事务，任意插入失败回滚整周。
6. 周布局函数不修改输入数组，重叠轨道上限固定，动态内容不会改变整体页面宽度。

## 当前限制

- 当前界面只加载包含今天的本周一至周日，不支持切换历史周或未来周。
- 同一份 ICS 会为范围内每一天分别执行有界解析；七天规模可控，但后续可改成单次区间展开以减少重复工作。
- 跨午夜事件会按每天的日内片段显示，没有跨行连接视觉。
- 自动同步仍由 WebView 定时器触发，托盘隐藏、休眠恢复和长期后台运行尚未迁移到 Rust 调度器。
- 浏览器模式使用演示日程；只有 Tauri 原生模式会读取 SQLite 和真实连接。
- 仍未实现 Google Calendar、Microsoft Graph 或飞书 OAuth，也不会向远端日历写入修改。
