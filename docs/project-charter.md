# Agent Bar 项目章程

状态：Draft v0.1

## 项目定义

Agent Bar 是一个桌面优先的个人时间与 Agent 协作系统。它把未来的计划、当前活动、过去的时间投入和 Agent 工作放在同一条时间轴上。

“Bar”目前只是桌面常驻入口的项目代号。最终形态可能是横向状态条、侧边轨道、浮动岛、托盘面板，或者几种形态的组合。

## 问题背景

用户的工作逐渐分散在日历、任务清单、本地应用和多个 Agent 之间，信息彼此割裂：

- 重要事项、截止日期和时间窗口容易遗漏。
- 每日计划很少与实际时间投入进行对照。
- 后台 Agent 的工作状态难以快速理解和干预。
- 日程、活动统计和 Agent 执行通常存在于不同工具中。

Agent Bar 应该让这些信息自然地出现在桌面工作流中，而不是成为另一个必须全天打开的全屏仪表盘。

## 产品闭环

1. 收集日程、截止日期、任务和 Agent 工作。
2. 安排当天计划和时间块。
3. 在执行过程中观察人和 Agent 的活动。
4. 自动记录应用和窗口使用情况。
5. 对照计划时间和实际时间。
6. 由 Agent 建议如何调整剩余日程。

## 产品原则

- 桌面优先，尽量减少打扰。
- 个人活动数据本地优先。
- 时间是人类活动和 Agent 活动的共同坐标。
- Agent 状态应先做到容易理解，再追求技术细节完整。
- Agent 的重要操作可中断，并在必要时等待用户批准。
- 通过适配器接入不同平台，不绑定单一 Agent 厂商。
- 虚拟工作场景必须帮助用户理解状态，而不只是装饰。

## 初始用户

第一阶段面向同时使用多个桌面应用和一个或多个 Agent 的个人知识工作者。架构可以为未来协作预留空间，但多人办公室、企业权限和组织管理不属于 MVP。

## 第一版非目标

- 替代完整的日历产品。
- 构建通用低代码工作流编辑器。
- 展示模型的原始思维链或每一个内部 Token。
- 首发时支持所有桌面应用和 Agent。
- 构建多人在线虚拟办公室。

## 项目阶段

### Phase 0：需求定义

- 确认主要工作流和信息层级。
- 原型比较多种桌面常驻入口。
- 定义带能力声明的 Agent 接入协议。

### Phase 1：体验原型

- 使用模拟的日程、活动和 Agent 数据。
- 验证日时间轴、计划与实际对照、虚拟工作场景。
- 根据原型测试结果选择桌面入口形态。

### Phase 2：本地纵向闭环

- 记录前台应用和窗口活动。
- 将事件保存在本地。
- 在同一日时间轴展示计划和实际活动。
- 接收一种真实 Agent 的事件流。

### Phase 3：Agent 控制与外部接入

- 根据 Agent 能力支持暂停、继续、终止、批准、优先级和任务移交。
- 增加 Codex 和 Claude Code 适配器。
- 接入 Notion 或飞书等信息来源之一。

### Phase 4：桌面 MVP

- 优先打包 Windows 桌面应用。
- 完成开机启动、托盘、通知、权限和异常恢复。
- 先验证日常使用价值，再扩展平台和接入生态。
