# Agent Bar 产品需求

状态：Draft v0.1

## 已确认的用户目标

产品需要帮助用户：

- 避免错过事项、截止日期和重要时间窗口。
- 用清晰的时间块安排当天活动。
- 自动了解每天每小时实际花在了哪里。
- 大致看懂当前 Agent 正在做什么。
- 让 Agent 帮助规划并动态调整日常活动。

## 第一版日常闭环

### 早晨规划

早晨规划是第一版的核心入口：

1. 同步系统日历、飞书、Notion 和用户主动导入的消息事项。
2. 提取今天的固定日程、临近截止日期、未完成任务和候选事项。
3. Agent 根据空闲时间、任务优先级和预计时长生成全天安排草案。
4. 明确标注冲突、信息不确定项和需要用户确认的安排。
5. 用户调整并确认后写入当天时间轴。

首次解锁电脑后使用轻量通知提示用户开始规划。通知可以延后 15、30 或 60 分钟，不强制弹窗或抢占焦点。

### 全天感知

- 常驻入口显示当前计划、下一个事项、延误情况和 Agent 待批准操作。
- 自动记录前台应用名称和经过本地脱敏的窗口标题。
- 实际进度偏离计划时，Agent 可以提出重新排程建议，但不直接覆盖用户锁定的时间块。
- Agent 虚拟工作场景用于快速理解当前有哪些 Agent 在工作、等待或失败。

### 晚间复盘

- 对照当天计划与实际时间投入。
- 展示完成、延误、跳过和临时增加的事项。
- 按类别聚合时间，并允许用户修正自动分类。
- 生成简短复盘，建议将未完成事项移动、拆分或取消。

## 核心信息模型

### 计划事项

占用或影响未来时间的日历事件、行程、截止日期、任务或专注时间块。

### 活动记录

根据前台应用和窗口自动采集的时间区间。第一版默认保存应用名称和经过本地脱敏的窗口标题。用户必须能够排除敏感应用、进一步隐藏窗口标题或暂停记录。

### Agent 运行

Agent 执行的一次工作单元，包括目标、状态、时间、Agent 身份、粗粒度活动类型、批准请求和产物。

### Agent 能力

由适配器声明的能力，例如观察、暂停、继续、终止、批准、调整优先级或任务移交。连接的 Agent 不支持某项操作时，界面不应假装能够执行。

## 必需产品界面

### 桌面常驻入口

最终形态暂不确定，原型阶段比较：

- 屏幕顶部或底部的横向状态条。
- 屏幕侧边的纵向轨道。
- 浮动紧凑岛。
- 托盘入口和全局快捷键展开面板。

紧凑状态只显示需要即时感知的信息：当前活动、下一个事项、紧急提醒、活动 Agent 数量和待批准请求。

### 日与周时间轴

- 显示计划时间块。
- 显示自动采集的实际活动。
- 对照计划和实际，同时保留两种原始信息。
- 按用户可配置的类别聚合活动。
- 支持日视图和周视图。
- 提示冲突、未安排时间和临近截止日期。

当前第一代已经用同一条 24 小时坐标展示周一至周日安排，支持横向滚动、重叠时间块分层、锁定日历标记和点击查看来源。历史周切换、跨天事件连线和空闲窗口建议仍待实现。

### Agent 虚拟工作场景

第一版采用简洁、可爱、直观的 2D 像素办公室，每个活动 Agent 或子 Agent 对应一个角色。动画由真实运行状态确定，不模拟与任务无关的复杂自主行为。场景、人物外观和工位布局需要为后期自定义预留资源接口。

所有已连接的主 Agent 在办公室中常驻。空闲 Agent 可以休息或闲逛，子 Agent 只在实际运行期间临时出现。

首批可视状态：

- 空闲或可用。
- 前往工作区域。
- 阅读或搜索。
- 编写或编辑。
- 运行工具或命令。
- 等待批准或用户输入。
- 阻塞或失败。
- 完成并回到空闲状态。

点击角色后展示任务名称、当前粗粒度动作、已用时间、父任务、最近产物和可用控制。原始详细日志放在可选的二级界面。

### Agent 控制

在适配器支持的情况下，用户可以：

- 暂停和继续一次运行。
- 终止一次运行。
- 批准或拒绝工具操作。
- 调整任务优先级。
- 将任务移交给另一个兼容 Agent。

任务移交是产品层能力。系统需要打包目标、必要上下文、产物和来源记录，不能假设不同 Agent 会自动共享记忆。

### 每日规划助手

- 根据任务、日历、截止日期和空闲时间提出当天计划。
- 解释重要的排程选择和冲突。
- 用户确认或修改后再应用建议。
- 出现延误或临时工作后重新规划剩余时间。
- 保留固定事项和用户锁定的时间块。

当前第一代实现了可编辑待办、优先级、预计时长、偏好时段、切换缓冲、全天草案、未排入原因、确认后原子写入，以及应用内每日提醒、延后 15/30/60 分钟、今日忽略和当日已规划标记。Windows 首次解锁/睡眠恢复通知、Codex 事项理解和自动重新排程仍待实现。

## 初始接入范围

### Agent 适配器

- Codex 作为第一个真实适配器。
- Claude Code 作为第二个适配器。

### 计划与知识适配器

- 系统日历作为第一批正式日程来源。
- Notion 数据源作为任务和项目来源。
- 飞书日历和经过授权的飞书消息作为事项来源。
- 微信通过用户主动转发、复制、截图或文件导入提取事项。
- 通过明确适配器或受控桌面操作连接其他本地应用。

接入能力分为三层：

- 正式双向 API：Notion、飞书日历和 Outlook/Microsoft Graph 日历。
- 正式授权事件：企业自建飞书应用接收授权范围内的消息事件。
- 用户主动导入：个人微信等没有合适官方读取接口的数据源。

第一版不读取或破解个人微信本地聊天数据库，也不承诺自动访问全部微信聊天记录。

微信事项导入的第一版只实现截图输入。后续再评估用户主动触发的一键本地会话接入或限时读取；任何读取都必须明确显示范围、持续时间和停止入口。

## 隐私与安全要求

- 前台窗口跟踪必须由用户主动开启，并持续可见。
- 用户能够排除应用、隐藏窗口标题和暂停跟踪。
- 原始活动数据默认只保存在本地。
- Agent 适配器声明权限和支持的控制能力。
- 破坏性或敏感操作必须明确批准。
- 外部写入需要记录请求 Agent 和批准用户。

## 暂定 MVP 优先级

### P0

- 当天计划时间轴。
- 自动记录前台应用和窗口。
- 计划时间与实际时间对照。
- Agent 事件接入和粗粒度实时状态。
- 显示待批准请求。
- 本地存储和隐私控制。

### P1

- 2D Agent 虚拟工作场景。
- 暂停、继续、终止和批准等基础控制。
- 每日规划和重新排程建议。
- 第一个 Codex 或 Claude Code 适配器。
- 早晨自动规划、全天调整建议和晚间复盘。

### P2

- 第二个 Agent 适配器。
- 调整优先级和跨 Agent 移交。
- Notion、飞书与系统日历的更多双向写入能力。
- 周时间统计和类别趋势。

当前第一代已完成本周七天真实日历安排、逐日实际/计划统计、四类时间去向和 Top Apps；历史周切换、类别趋势比较与导出仍待实现。

## 已确认的日历接入顺序

- 第一代先支持 ICS 文件导入，覆盖主流日历的通用导出格式。
- ICS 导入只读、先预览再确认，不保存原始文件，不覆盖手动或锁定时间块。
- 持续 ICS 连接一次读取后同步本周七天；各来源独立、整周原子替换，解析失败时保留旧数据。
- 持续连接由 Rust 后台线程按间隔检查，主窗口隐藏到托盘后仍运行；工作台通过原生事件接收同步结果。
- 后续账号直连的优先级依据实际使用选择 Microsoft Graph/Outlook、Google Calendar 或飞书。
