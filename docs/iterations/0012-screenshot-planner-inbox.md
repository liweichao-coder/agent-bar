# Iteration 0012: Screenshot Planner Inbox

状态：Implemented and verified; live Codex vision run still requires desktop authentication smoke test

## 目标

把微信、飞书和通知截图转成可校对的日程事项，并接入既有晨间规划器；同时让这次 Codex 工作出现在 Agent 办公室，而不是新增一套不可观察的后台 OCR 流程。

## 本轮完成

- 新增“截图提取”入口和原生对话框，支持 PNG、JPEG、WebP，单张上限 8 MB。
- 截图以 Codex App Server `localImage` 输入发送，使用 `original` 细节等级，不依赖手写 OCR 或固定模板。
- 每次分析创建只读、无需工具批准、临时的 Codex thread，不能执行命令或修改工作区。
- 通过动态工具 `submit_extracted_tasks` 强制返回结构化事项，不读取或持久化 Agent 消息正文和推理内容。
- 工具结果经过 Rust 二次校验：最多 30 项，标题/备注/警告有长度上限，时长必须是 15 至 480 分钟的 15 分钟倍数，优先级、时段和类别必须来自固定枚举。
- 分析任务同步进入 Agent 办公室，显示“从截图提取日程事项”的工作状态和已提取数量。
- 分析中可独立终止；成功、失败、终止、连接中断和对象销毁都会尝试删除临时图片。
- 提取结果支持逐项修改标题、时长、优先级、偏好时段和类别，也可以删除误识别事项。
- 不确定信息以警告展示，必须由用户确认后才加入本地待办。
- 确认后进入既有“安排今天”流程，继续由确定性排程器处理已有安排、优先级、偏好时段和无冲突约束。
- 状态轮询只在收到一批新的结果时初始化编辑草稿，不会覆盖用户正在校对的修改。

## 隐私与安全不变量

1. 前端先限制 MIME 和大小，Rust 再用文件魔数与 MIME 联合校验，不能只相信扩展名。
2. 原图只写入应用缓存目录的临时文件，不写入 SQLite，也不进入项目工作区。
3. 用户选择后，原图会发送给当前登录的 Codex 服务用于视觉理解；界面明确提示这一数据流向。
4. 临时文件只活到结构化工具返回、失败、终止或连接中断；运行时析构仍有兜底清理。
5. 截图 thread 使用 `read-only + approvalPolicy: never + ephemeral`，这一流程不需要任何命令或文件工具。
6. Agent Bar 只接收受 schema 约束的事项与警告，不展示或保存 Codex 的消息正文和推理过程。
7. 结构化事项仍只是草稿；用户确认前不会进入待办或时间轴。
8. 保存到 SQLite 的只有用户确认后的结构化事项，不保存原截图。

## 协议边界

- 输入：App Server v2 `UserInput.localImage`，路径指向 Agent Bar 临时缓存。
- 输出：App Server server request `item/tool/call`，工具名为 `submit_extracted_tasks`。
- 响应：`DynamicToolCallResponse` 的 `contentItems + success`，Agent Bar 在返回响应前完成校验和临时图清理。
- 可视化：同一个临时 thread 同时映射为 `ManagedCodexRun`，复用办公室、计时和终止控制。
- 排程：视觉理解只负责提取语义，时间约束继续由本地确定性规划器负责，避免模型直接制造重叠日程。

## 当前限制

- 本轮没有把包含私人信息的真实截图发送给 Codex；需要在 Tauri 桌面版已登录环境中做一次用户主动选择的端到端烟雾测试。
- 第一版只支持文件选择，不支持剪贴板粘贴、拖放、系统分享菜单或从微信窗口一键截取。
- 截图中的绝对日期、相对日期和时区目前只保留在标题/备注/警告中，尚未形成带截止时间的独立字段。
- 不能把多张截图合并为同一个上下文，也没有重复事项检测。
- Codex 是当前唯一视觉理解提供方，尚未抽象成 Claude Code 或本地视觉模型适配器。
