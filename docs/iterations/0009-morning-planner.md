# Iteration 0009: Morning Planner

状态：Implemented and verified; automatic in-app prompt completed in Iteration 0010

## 目标

把静态“剩余时间建议”升级为可编辑、可预览、可确认的全天规划闭环，并让日历和已有时间块成为真实排程约束。

## 本轮完成

- 新增纯 TypeScript `buildMorningPlan` 排程核心，浏览器原型和 Tauri 共用同一结果。
- 待办支持标题、15 至 240 分钟时长、四级优先级、偏好时段和活动类别。
- 规划范围支持开始、结束和 0 至 30 分钟事项切换缓冲。
- 所有已有时间块均被保留并参与占用计算，日历锁定项不会被移动或覆盖。
- 同优先级下优先放置更长任务，提高有限空档的可用率。
- 偏好时段没有完整空档时自动尝试其他时段，并在草案中说明回退原因。
- 无法完整放入的任务返回明确原因并继续保留在待办队列。
- 草案显示已有安排、新增任务和剩余可用时间，并列出每个新增时间块。
- SQLite 升级到 v7，持久化待办队列。
- 新增 `apply_morning_plan` 原生命令，在单个事务内保存全天时间轴与剩余待办。

## 安全不变量

1. 不修改或删除与本次任务 ID 无关的已有时间块。
2. 不生成重叠任务。
3. 不把无法安排的任务伪装成已完成或已排入。
4. 日程与待办同步提交；任一数据库约束失败则整体回滚。
5. 用户确认前只生成内存草案，不写入时间轴。

## 验证证据

- Node 测试 6 项通过：已有事项和缓冲、优先级、偏好回退、未排入、输入不可变、无效范围。
- Rust 测试 20 项通过，2 项真实 Codex 登录测试忽略。
- 数据库测试主动注入无效待办，确认时间轴和待办整体回滚。
- 桌面交互验证：两项待办生成 `22:45-23:15` 和 `23:30-24:00` 草案；确认后时间轴新增两项、待办清空。
- 390x844 响应式验证：对话框完整位于视口内，任务列表纵向滚动，底部确认按钮持续可达。
- 浏览器控制台无 warning 或 error。

## 当前限制

- 首次解锁或系统通知仍未实现；应用内早晨提示已在 Iteration 0010 完成。
- 待办目前由用户编辑或示例数据产生，尚未由 Codex、Notion 或飞书自动提取。
- 第一代不自动拆分长任务，也不根据精力曲线或历史实际耗时调整估时。
- 浏览器演示状态不跨刷新；Tauri 模式使用 SQLite 持久化。
