# Iteration 0010: Morning Reminder

状态：Implemented and verified; system unlock notification remains pending

## 目标

让晨间规划从用户主动打开的工具升级为每日可感知入口，同时避免重复打扰，并把提醒状态纳入本地事实来源。

## 本轮完成

- 新增纯 TypeScript `evaluateMorningReminder` 状态机，浏览器原型与 Tauri 共用到期判断。
- 每日提醒支持启用/关闭与 06:00 至 11:00 的半小时时间档。
- 到期后在工作台显示持续提醒带，不抢焦点，不使用会自动消失的 toast。
- 提醒带显示待安排事项和已有日程数量，并提供开始规划、延后 15/30/60 分钟和今天忽略。
- 同日延后在目标时间后重新出现，显式延后最晚可延伸到 18:00；普通提醒窗口在中午或配置时间后四小时结束。
- 前一天遗留的延后时间不会跳过次日配置时间。
- SQLite 设置保存提醒开关、提醒分钟、延后截止时间、当日忽略和最近完成规划日期。
- 确认全天安排时，在同一事务内写入日程、剩余待办和“今日已规划”，并清除延后与忽略状态。
- 晨间规划器内提供提醒开关和时间设置。

## 状态不变量

1. 当天已确认规划或已选择今天忽略时，不再显示提醒。
2. 关闭提醒后，任何时间都不显示提醒。
3. 延后只覆盖同一天；旧延后不能改变次日提醒窗口。
4. “今日已规划”与日程、剩余待办原子提交；事务失败时三者都不更新。
5. 浏览器调试查询参数只用于界面验收，不进入桌面版业务状态。

## 验证证据

- Node 测试 12 项通过，其中 6 项覆盖到期时间、已规划/忽略、延后、跨日、结束窗口和关闭状态。
- Rust 测试 21 项通过，2 项真实 Codex 登录测试忽略。
- 数据库测试确认提醒设置可恢复、确认规划会清理延后/忽略，并验证无效待办导致事务回滚时不会写入“今日已规划”。
- 1280x720 验证：提醒操作区完整位于提醒带内，页面无横向溢出。
- 390x844 验证：提醒操作换行后仍位于容器内，规划器提醒设置不超出对话框。
- 实际交互验证：延后 30 分钟后提醒立即隐藏；修改提醒时间和开关生效；确认两项全天任务后提醒消失。
- 浏览器控制台无 warning 或 error。
- `cargo clippy --all-targets --all-features -- -D warnings` 通过。

## 当前限制

- 当前提醒只在 Agent Bar 已启动且工作台可见时呈现，不监听 Windows 首次解锁、睡眠恢复或登录事件。
- 尚未使用系统通知；紧凑状态条不会主动展开完整工作台。
- 浏览器演示状态不跨刷新；Tauri 模式使用 SQLite 持久化。
- 尚未按工作日、节假日或不同日历配置不同提醒时间。
